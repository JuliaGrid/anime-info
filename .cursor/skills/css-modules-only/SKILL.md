# Только CSS Modules

## Цель

Поддерживать единый и предсказуемый подход к стилизации, используя CSS Modules как стандарт для стилей компонентов.

## Инструкции

1. Если нужна стилизация, создавай или обновляй файлы `styles.module.css`.
2. Импортируй модульные стили в компонент (например: `import classes from './styles.module.css'`).
3. Используй классы через объект модуля в разметке (`className={classes.card}`), а не через строки глобальных классов.
4. Именуй CSS-классы строго по БЭМ: `block`, `block__element`, `block--modifier`.
5. Предпочитай доступ к классам через точку: `classes.app__content`, а не через скобки: `classes['app__content']`.
6. Сохраняй локальную область видимости селекторов; не выноси стили компонентов в глобальные таблицы стилей.
7. Если в затронутом коде используется другой подход, по возможности безопасно мигрируй его на CSS Modules.

## Допустимые исключения

- Общие для всего приложения reset/theme/token файлы, которые должны быть глобальными по смыслу.
- Обязательные стили сторонних библиотек, которые нельзя конвертировать.

## Избегать

- CSS-in-JS библиотеки для новых или изменяемых компонентных стилей.
- Глобальные CSS/SCSS файлы для стилизации отдельных компонентов.
- Utility-классы как замену модульным файлам стилей.
- Единицы `rem` и `em` в значениях стилей.
- Имена классов вне методологии БЭМ.
- Обращение к классам через квадратные скобки без необходимости.
